本轮游戏交互全部通过 Python stdio MCP 的 `tools/call` 转发到正在运行的 Mod；没有使用桌面键鼠、截图、控制台、代码注入或直接修改游戏/存档来替代 MCP 操作。令牌只由客户端读取本机已有配置用于认证，不记录值。

用户已手动进入测试存档。此前主菜单握手/观察成功，`scene=EmporiumMenu`、`in_run=false`，没有动作句柄。本轮测试场景为 `InventoryScene`、`in_run=true`。

## 已实际通过（运行中 0.1.1）

1. MCP initialize / tools/list：服务 0.1.1，六项工具可发现。
2. observe：返回真实第1天、550信用点、今日事件、可见物品与场景控件。
3. 初始可见物品 12 项，含储藏区、牙膏、厕纸、果汁、合成肉、档案箱、垃圾桶、播放器等；不把候选动作当成已验证可执行。
4. inventory：复用观察快照，按 limit=3 分页，前两页没有重复 handle，snapshot 保持一致。
5. 连续两次 observe 后，第一份 snapshot 调 inventory 返回 `unavailable`，拒绝旧快照。
6. 使用不存在的 snapshot 返回 `unavailable`。

没有开店、交易、消费物品、睡觉、推进日期或移动物品。仅打开储藏区改变了窗口显示状态；没有宣称读取到的局面足以证明全部存档字段未改变。

## 发现的阻断问题

- 初始 observe 有 item/world/text，**没有 inventory 或 pixel_button**。
- 打开储藏区后，仍没有容器空白区域句柄、原生窗口关闭按钮。
- 因此 `game_move_item` 虽然有协议和原生转移逻辑，但在这个真实场景中拿不到目标 inventory，无法正常使用；打开窗口后也无法通过已有接口可靠关闭。
- 此问题此前编译、协议模拟和静态扫描均未发现。必须先修真实原生渲染节点命中/枚举，再在重启换版后复验，不以放宽隐藏控件或桌面输入绕过。
